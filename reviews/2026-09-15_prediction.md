### 为什么「30 档没有 edge」值得单独讲

30 档的条件概率跳变极大，**而且方向相反**：

| 当日雨量情景 | n | P(30档) | 对应动作 | EV |
|---|---:|---:|---|---:|
| <2mm（最干） | 22 | **4.5%** | 买 NO30 @0.840 | **+13.7%** |
| <5mm | 337 | 11.6% | 买 NO30 @0.840 | +5.2% |
| 5–20mm（中雨） | 60 | 23.3% | 买 YES30 @0.170 | +37.1% |
| 前日≥20 & 当日 5–20mm | 24 | **37.5%** | 买 YES30 @0.170 | **+120.6%** |
| ≥20mm（大雨） | 80 | 17.5% | 两边都不做 | — |
| **三情景加权** | **477** | **16.3%** | **两边都不做** | **−4.2% / −0.3%** |

**最容易误读的一格**：「前日≥20 & 当日 5–20mm」给 30 档 37.5%（n=24），对应 YES30 的 +121% EV。
但它只是**雨量开关的一个方向**，不是市场的系统性错误。按雨量概率加权（权重 0.35）后只贡献 13.1pp，
加权总期望 16.3%，与市场 16.5% 只差 0.2pp。

**这恰恰是市场有效性的体现** —— 市场把「明天雨量未定」这个不确定性直接定价进了 30 档。

## 12.3 🚨 本轮核心发现：L 必须收缩，而收缩后我方 = 市场

`watch()` 用的是「今日已采样时段的整点对齐中位偏差」，**不向气候值收缩**
（v0.16.10 立的规，理由是「封顶在气候值会在干燥晴热天硬砍 1.4°C」）。
但那个理由针对的是 `min(cur_bias, 气候偏差)` 这种**硬截断**，不是贝叶斯收缩 ——
当年把两件事混为一谈了，**修得过正**。

正确的层级模型：`L ~ N(μ_prior, τ²)`，观测 `L̂ ~ N(L, σ²)`，后验

```
L* = (μ_prior/τ² + L̂/σ²) / (1/τ² + 1/σ²)
```

今天三个量全部可测：

| 量 | 取值 | 来源 |
|---|---:|---|
| `μ_prior` | **+1.012** | `model_calib.json` 的 `bias`（80 天，站点日最高 − 7 模式平均日最高） |
| `τ` | **0.763** | `model_calib.json` 的 `resid_sd` = 该偏差的**逐日标准差** |
| `L̂` | **−0.95**（中位）／**−0.71**（均值） | 今日三个整点对齐样本 +0.23 / −0.95 / −1.40 |
| `σ` | **0.48 – 0.84** | 上述 3 样本：均值的 SE 0.48｜中位的 SE 0.60｜原始 sd 0.84 |

```
σ = 0.48（均值口径） → L* = −0.216
σ = 0.60（中位口径） → L* = −0.197
σ = 0.84（原始口径） → L* = +0.119
                    ⇒ L* ∈ [−0.22, +0.12]，中心 ≈ −0.15
```

**τ（0.763）与 σ（0.48–0.84）同量级 → 数据无法压过先验，收缩是强制性的：**
把 `L̂ = −0.95` 拉回 **−0.20 左右**（约 75% 的收缩量）。
顺带一提，`σ = 0.84` 那一档给出的 **L* = +0.119** 几乎正好落在市场隐含值上。

今天的 `L̂ = −0.95` 在 `N(+1.012, 0.763²)` 下是 **0.5% 分位**的事件（三个样本全负更是）；
要么今天确实异常，要么「逐时偏差」的均值本来就不等于「日最高偏差」的均值 ——
**这个先验均值到底该取多少，是本工具当前最大的未知量（见 §12.9）。**

## 15.2 🚨 方法学核心：逐时偏差 ≠ 日最高偏差

到上一轮为止，L 一直取「今日整点对齐的**逐时**偏差」。今天的数据第一次允许**直接检验**这个假设：

```
L̂(12h) = 29.4（站点 12:00） − 29.26（网格 12h） = +0.14
```

而 `model_calib.json` 的 `bias = +1.012` 是「**日最高**」偏差。**两者差 +0.87°C —— 这不是噪声，是有机制的：**

网格 `13h → 16h` 塌陷 `29.47 → 28.83 = −0.64`（对流参数化：模型认为午后会下雨）。
今天该时段**实际全港 0 mm、雷暴警告已取消** → 站点不会同样塌陷。所以

```
L_day ≈ L̂(12h) + 网格午后塌陷幅度 ≈ +0.14 + 0.64~0.87 ≈ +0.78 ~ +1.01
```

**这正好落在气候先验 +1.012 上 —— 两条完全独立的路径自洽。**

> **结论：用逐时偏差的均值（今天 −0.03）去收缩 `L_day`，是系统性偏低。**
> §12.3 定的「L 必须收缩」方向本身是对的，但**被收缩的观测值选错了变量**。
> 收缩的观测必须是「峰值时刻的偏差」，或直接 `L_day ≈ L̂(t) + 网格午后塌陷幅度`。

⚠ **唯一反面前提**：若下午真的转多云/有骤雨，网格的塌陷就是**对的**，`L_day` 掉回 +0.14 →

## 16.3 🚨 L 积分的系统性偏差：低档被抬高

本轮暴露一个新问题。同一个 L 中心，两种口径给出**差 6.2 个点**的 29 档概率：

```
单点 L=+0.90  →  29 档 19.0%
L 积分          →  29 档 25.2%      （+6.2pt）
```

原因：`mx = 29.6` 紧贴 30.0 档位边界（差 0.4°C）。L 积分会往下铺开 L 的分布，
每一个偏低的 L 都把 `pred` 压到 30.0 以下，**整块质量直接落进 29 档**，
而往上偏离的 L 只让 30 档变宽、不会把质量送给 31 档（31 档的边界在 31.0，还差 1.4°C）。

**结论（已写入 SKILL.md）：当 `running_max` 距档位边界 < 0.5°C 时，
L 积分的「下边界档位」会被系统性抬高；此时必须以单点口径作为该档的概率下界报出。**

对本轮的意义：29 档的真实概率区间是 **19%（单点）~ 25%（积分）**，
而不是「25.2% 一个数」。相应地 `NO29` 的公允是 **74.8% ~ 81.0%**。

根因是 watch 支路有三处口径错，全部在 v0.16.22 修掉：

### ① base 用错（最严重）：当前瞬时值 vs running max

分位表的原生定义写在 `build_remaining_rise.py` 表头：

```
"def": "R(h) = M - running_max(h)  (remaining rise, >= 0)"
```

**基准是 running max，不是当前值。** watch 路径却用 `need = b − hko_t`。
今天 `hko_t = 30.2`、`running_max = 31.4` → need 从 **+0.6 被虚增到 +1.8**，
等于凭空要求「站点先涨回峰值再涨 0.6」。**回落日必错**（涨势日两者相等，所以此前从未暴露）。

### ② δ 被钳死在 −1.00：把「口径失效」当「硬惩罚」

站点 31.4 早已越过**网格全天峰值 29.49**，于是 `ρ̂ = (g_rest + L) − mx = 27.65 − 31.4 = −3.75`，
`δ = clamp(−3.75 − 0.13) = −1.00`。这与 v0.16.21 在 `l_integrate` 里修掉的是**同一个 bug**，
只是当时只修了一边。现在两边都改成：**越过网格峰值时 δ 归零**（退回纯气候）。

### ③ 两条路径的概率公式不同源

watch 是**网格口径直读**（need 不除放大比、无回落腰斩），l_integrate 是站点口径
（`need/k_R` + δ 归零 + 回落 ×0.5）。现抽出 `hk_edge.station_reach_prob()`，
**与 `l_integrate.bucket_probs_at_L` 的经验支路逐字同源**。

修正后 watch 输出：

```
到 32.0°C  需再升 +0.6°C（基准=已观测最高 31.4）→ 站点口径 11%   ⓘ 网格口径下限 3%
到 33.0°C  需再升 +1.6°C（基准=已观测最高 31.4）→ 站点口径 2%    ⓘ 网格口径下限 0%
```

**物理含义**：

用的是**日内最大回撤**。今天证明了：
**「今天曾经回撤过」不重要，「现在是否已从回撤中修复」才重要。**
今天日内最大回撤 1.4°C（31.4→30.0，比上轮记录的 1.1 更深），但 14:00 只差峰位 0.3°C
→ 应取 **46.4%**，不是 11.7%。

> **新规则（取代 v0.16.21 的腰斩条款）：条件变量必须用「当前 gap」，不能用「历史最大回撤」。**
> 若确实要保留回撤记忆，只能作为**次级**修正，不能覆盖 gap 的主判。

# §21 14:40 轮：**状态在 10 分钟内反转** —— gap 是台阶不是斜坡，且这解开了「24% vs 43%」的长期分歧（v0.16.25）

| 14:20 | 31.1 | 0.3 | 0.725 | 0.200 |

| 14:31 | 30.4 | 1.0 | 0.725 | 0.200（**市场还没动**） |

**站点在 10 分钟内跌 0.7°C（31.1 → 30.4），gap 从 0.3 跳到 1.0**，越过 0.5 这条线。

## 21.2 决定性的一张表：gap 的两侧是**台阶**，不是斜坡

VHHH 九月，`rm ≈ 31` 层级，按 `gap = rm − cur` 切：

| 时刻 | `gap ≤ 0.5` | `gap > 0.5` | 倍数 |
|---|---:|---:|---:|
| 14:00 | **46.4%** (n=28) | **10.5%** (n=19) | 4.4× |
| **14:30** | **30.8%** (n=26) | **5.0%** (n=20) | **6.2×** |
| 15:00 | 14.3% (n=21) | 4.5% (n=22) | 3.2× |
| 14:30（全部 rm 级别） | 27.9% (n=183) | 7.5% (n=147) | 3.7× |

（数字 = `P(最终日最高 ≥ rm + 1)`，即「升到下一档」）

两条同时成立、都必须用的规律：

1. **gap 是一道台阶**：跨过 0.5，概率**掉 4–6 倍**，不是平滑下降。
2. **时间本身也在衰减**：同为 `gap≤0.5`，14:00 的 46.4% → 14:30 的 30.8% → 15:00 的 14.3%。

**今日 14:30 落在 `gap>0.5` 格 → P(≥32) ≈ 5.0%。市场给 5.5%（14:40），基本一致。**
**§20 的 42% 是基于 14:20 状态（gap=0.3）的正确读数；14:30 状态一变，正确的读数就是 5–8%。**

## 21.3 顺带解开了一个长期悬案：网格模型的 24% vs 站点口径的 43%

前四轮反复记录的「站点口径 43% vs 网格模型 24% 差 2 倍，无法判定谁对」，**本轮解开了**：

```
14:30, rm≈31:  gap≤0.5 → 30.8% (n=26)
               gap>0.5 →  5.0% (n=20)
               加权平均 = (26×30.8 + 20×5.0) / 46 = 19.6%
l_integrate 同一时刻给出          = 22.0%
```

**两者吻合。** 网格模型给出的不是「条件概率」，而是**对 gap 两侧的无条件平均** ——
它的 R 分位表是按「时刻」建的，**根本没有 gap 这个自变量**。

所以：

- **模型没有偏低**，它回答的是另一个问题（「平均而言还能升多少」）。
- 前四轮把两者当成「两个互斥的估计」在争，**是口径错误**：
  一个是条件概率，一个是边缘概率，本来就不该相等。
- 推论：**报概率时必须声明是条件还是边缘**。要下注用**条件**（gap 分侧）；
  要校准、算 Brier 用**边缘**。


## 22.4 四条硬教训（带数字）

### 教训 1｜合并档位头寸的「伪安全」

`NO31` 一个词覆盖 3 个互不相干的结局（≤29 全部 + 30 + ≥32 全部）。早盘市价 0.716 的
「71.6% 安全」里，**绝大部分来自「≤30」那一支**，而这一支随升温**单边、不可逆地蒸发**：

| 时刻 | 站点 | 「≤30」分支 | 「≥32」分支 | 合并 P(非31) |
|---|---:|---:|---:|---:|
| 09:15 | 27.6 | ~65% | ~7% | **~72%**（市价 0.716） |
| 12:50 | 31.3 | **0**（已死） | 27.4%（我方）/ 44%（市场） | **27.4%** |

**3 小时内，头寸的"安全性"从 72% 掉到 27%，而仓位一份没动。**
用合并后的单一百分比评估一个含单向风险的合成头寸 = 把负相关分支当独立事件加总。**禁止再用**。

### 教训 2｜13:20 之后四次加仓不是四个赌注，是一个赌注乘 4

13:20 / 13:45 / 14:11 / 14:30 四次 NO31 加仓（@0.20 / 0.22 / 0.345 / 0.39，合计 **$250.67**，
是早盘首推 $100 的 2.5 倍）**全部发生在同一个条件格**：`rm=31.4, gap ≤ 0.5`。
格内概率是同一条数字（46.4%, n=28）—— **下单不产生新信息，只把同一个 46% 的注码乘 4**。

而且这四条建议**互相取代/作废**（14:11 撤 13:45、14:30 撤 14:11、13:45 撤 13:20）——
**建议层面自己在 70 分钟里翻烧饼 4 次，用户即使想跟也无法复现**。这是决策噪声，不是决策。

> ⚑ 真实头寸的均价停在 **0.716**，说明这四次**用户一次都没执行**。
> **这是今天唯一救了账户的事**：若四次全部成交，NO31 成本将从 $320.77 扩到 $571.44，亏损扩大 53%。

### 教训 3｜格均值 ≠ 当日读数：n<30 的条件概率只能定方向，不能定幅度

`gap≤0.5 → 46.4%（n=28）` 是**格内均值**。今天两个处于该格的时段（14:00–14:20）最终都没跨到 32.0。
**这不是 46.4% 这个数错了** —— n=28 的格里，「没上去」本来就是 53.6% 那一边的常见结果。
**错的是我把格均值当成了当日的精确读数**。单日只有一个样本时，格均值几乎不含当日信息。

规则：`n < 30` 的条件格，**报区间不报点值**，当日只用于定方向（上侧 / 下侧），不用于算 Kelly。

### 教训 4（流程）｜我撤回了当天唯一正确的动作

12:33 卖 NO29 @0.935、13:20 卖 NO29 @0.995 ——「29 档必然归零」是全天**唯一被实况完全确认**

规则：撤回只能作用于**未成交挂单**；已成交腿的后续优化必须另立「持有 / 减仓建议」条目，不得 void 原记录。
