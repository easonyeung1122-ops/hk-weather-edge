### 2.4 gap（当前回落幅度）与冷池日

#### 定义：条件变量是**当前 gap**，不是「今天曾经回落过」`[v0.16.23 修正 v0.16.21]`

```
gap = running_max − 当前值      ← 用同一序列（0.1°C 源）自己的 running max
```

同一个 VHHH 九月样本（n=330），14:00 时按 `gap` 切分：

| 14:00 条件 | n | P(创新高) | P(再升 ≥2°C) |
|---|---:|---:|---:|
| **gap ≤ 0.5°C** | 193 | **37.8%** | 2.1% |
| gap > 0.5°C | 137 | **11.7%** | 0.0% |
| 无条件 | 330 | 27.0% | 1.2% |

再按 `rm` 级别细分：

| rm 级别 | n(gap≤0.5) | P(升1档) | n(gap>0.5) | P(升1档) |
|---|---:|---:|---:|---:|
| 30 | 15 | 46.7% | 13 | 15.4% |
| **31** | **28** | **46.4%** | 19 | **10.5%** |
| 32 | 55 | 40.0% | 34 | 14.7% |
| 33 | 54 | 37.0% | 30 | 10.0% |
| 34 | 23 | 17.4% | 14 | 0.0% |

> **v0.16.21 那条「盘中回落 ≥0.5°C → 概率腰斩」已被实况推翻，见 `references/archive_retracted.md`（7-A-2）。**

1. 报告「还需再升 X°C」的概率时，条件变量取 **`gap = running_max − 当前值`**（**当前时刻**）；
2. `gap ≤ 0.5` → 用贴近峰位的那一侧（`l_integrate --pullback` 不触发）；
   `gap > 0.5` → 走回落那侧。**日内最大回撤只作次级记录，不得覆盖 gap 主判**；
3. 引用条件概率时必须同时报 **`rm` 级别**（按 `rm` 取隔壁 ±0.5 的子集，样本 <8 时退回单条件）；
4. **14:00 之后仍不能收工**：VHHH 九月峰值时刻分布 14 时 66 天 / 15 时 44 天 / 16 时 14 天
   → **38.8% 的日子在 14:00 之后才成峰。**

#### gap 是一道**台阶**（跨过 0.5 掉 4–6 倍），不是斜坡 `[v0.16.25]`

VHHH 九月，`rm ≈ 31` 层级，数字 = `P(最终日最高 ≥ rm + 1)`：

| 时刻 | `gap ≤ 0.5` | `gap > 0.5` | 倍数 |
|---|---:|---:|---:|
| 14:00 | **46.4%** (n=28) | **10.5%** (n=19) | 4.4× |
| **14:30** | **30.8%** (n=26) | **5.0%** (n=20) | **6.2×** |
| 15:00 | 14.3% (n=21) | 4.5% (n=22) | 3.2× |
| 14:30（全部 rm 级别） | 27.9% (n=183) | 7.5% (n=147) | 3.7× |

**两条同时成立、都必须用：**
1. **gap 跨过 0.5 是一道台阶** —— 概率掉 4–6 倍，不是平滑下降。
   2026-09-15 实测：站点 14:20 的 31.1（gap 0.3）→ 14:30 的 **30.4**（gap **1.0**），
   公允从 0.42 掉到 0.07（**6 倍**），盘口 13 分钟内把 32 档从 0.200 砸到 **0.020**。
2. **时间本身也在衰减** —— 同为 `gap≤0.5`：14:00 **46.4%** → 14:30 **30.8%** → 15:00 **14.3%**。
   所以引用任何一个概率都必须**同时给 hour 与 gap 侧**。

#### 仓位建议必须绑定「数据时刻」并写作废条件 `[v0.16.25]`

2026-09-15 实测：基于 14:20 实况（gap=0.3）算出的 P(32)=0.42，
在 **15 分钟后**被 14:30 的实测推翻成 0.07。**建议的有效期 = 到下一个 10 分钟观测为止。**

**硬规则**：每条仓位建议后面必须写清

```
数据时刻：HH:MM（用的是哪一刻的实况）
作废条件：若下一批 0.1°C 实测 gap > 0.5（或 < 某阈值），本条立即作废并重算
```

**不要用 10 分钟前的实况给 10 分钟后的建议** —— `latest_1min_temperature.csv`
每 10 分钟滚动一次。

#### 冷池日：网格主公允表整张不可用，改读 `--watch` `[v0.16.3→v0.16.6 → v0.16.21 修 bug]`

**触发条件（v0.16.6，最终版）**：**当天曾出现过 ≥0.5°C 的回落**，且这个事实**记在日内记忆里，只增不减**。
判据是当日**最大回撤** > 0.5°C，而不是「此刻的即时落差」、也不是「日较差」：

```python
_cold_gap = _load_cold_pool_gap(today) or 0.0
if (floor_max - fl_cur) > _cold_gap:
    _cold_gap = floor_max - fl_cur        # 只增不减
_save_cold_pool_gap(today, _cold_gap)     # 落盘 scripts/data/cold_pool_state.json
if _cold_gap > 0.5:
    _cold_pool = True
    _cold_relaxed = (floor_max - fl_cur) <= 0.5   # 冷池已退 → 放宽标记，但不解除作废
```

⚠ **三代错误判据，都别再写回去**：

| 版本 | 判据 | 为什么错 |
|---|---|---|
| v0.16.3 | `落差 > 1.5°C` | 数值写错 —— 站点 13:08 从 26.2 反弹到 27.9、落差只剩 0.8，规则不触发，作废表（28 档 2.7%）又被读出来 |
| v0.16.4/5 | **即时**落差 > 0.5°C | 14:03 站点从 27.9 反弹到 28.5、落差缩到 0.2 → **作废静默解除**，回到 v0.16.3 的错误状态 |
| **v0.16.6** | 日内**最大回撤** > 0.5°C | 正确 —— 冷池是「今天已经发生过的事」，不是「现在还差多少度」 |

⚠ **v0.16.21 修掉两个叠加的口径错误**（2026-09-15 13:06 主表把 31/32/33 三档整段标
「⚠作废(冷池日)」，理由是「今日曾出现 **3.7°C** 的回落」—— **当天从来没有 3.7°C 的回落**）：

1. **`_cold_gap_from_logs()` 曾取日较差**（旧代码 `max(vals) − min(vals)`）。
   `obs_1min_log.json` 的序列从早上 08:50 开始 —— **正好是日最低附近** ——
   于是 `max(vals) = 31.3`（12:50 峰）− `min(vals) = 27.6`（08:50 晨低）= **3.7**。
   **任何晴热天都会触发这条兜底，把主表上三档整段作废。**
   ✅ 修正为**最大回撤** `max_t (running_max(t) − value(t))`；单调上升的一天恒为 0。
2. **gap 的两个端点曾来自不同源、不同刻**：`floor_max` 取三源最大
   （可能来自延迟仅数十秒的官方 `Max Since Midnight`），`fl_cur` 来自
   **延迟 10–25 分钟**的 0.1°C 分区 CSV。快速升温 / 回落的转折点必然出错。
   ✅ 修正为 gap 一律用**同一序列**（0.1°C 源）自己的 running max。

**硬规则：任何「端点相减」的判据，两端必须来自同一个接口、同一次采样。**
跨源相减在本工具已经踩过三次（逐时偏差 vs 日最高偏差、best_match vs 7 模式平均、本条）。

修正后重跑同日：gap = **1.1°C**（真实的 31.3 → 30.2 回落），作废**仍然成立**，
但触发理由终于是真事件。

**为什么冷池日主表不可用**：主公允表（`--date ... --market ...`）的公允 = 「无天气型条件的气候期望点估
（bias 修正后的 7 模式集合均值）」+「残差 sd 0.76 的正态」。**它一个已实现事实都不吃** ——
既不看当日已观测最高，也不看当前温度、不看雷达/雨量。
2026-09-14 实测：站点当日最高已 **28.7°C**、正午 UV 只有 4、本区强对流，
主公允表仍给点估 **30.53°C**、28 档公允 **2.7%**；
**同一次运行里的 `--watch` 给的峰值是 28.60°C（差 1.9°C）。两个引擎方向相反，输出里没有任何提示。**

**规则（已在 `hk_edge.py` 实现，不必人工记得）**：
1. **主表那一行直接标作废**：作废档的动作列显示 `⚠作废(冷池)`，EV / Kelly 两列留空；
   表后声明「整条分布被高估，本次运行的动作 / EV / Kelly 整体不可作为下单依据」；
2. **冷池判定不再依赖 `--hold`**：判定移到主表之前，**不喂持仓也能看到作废提示**；
3. **持仓检查里落在作废范围的腿不再输出公允值与 EV**，改为 `⚠ 网格公允作废（…）→ 看 --watch`；
   **范围是 `b >= floor(当日最高)`**，标签两种：
   - `冷池日`：`b <= floor(当日最高) + 1`
   - `冷池退·封顶档`：更高档
4. **`⚠止盈` 标签全表屏蔽**：只要冷池成立，网格分布整条被高估，
   任何「市价高于公允」的结论都不可信；
5. **σ_flicker 守卫在冷池退时仍要跑**：`if _cold_reason and not _cold_relaxed` ——
   旧代码只要冷池成立就跳过守卫，等于**放弃唯一的实况口径**；
6. **σ_flicker 的随机游走起点必须是当前值**，不是当日最高：
   `_d_ref = fl_cur if fl_cur is not None else floor_max`。
   9/14 误报 `28YES 公允 0.5%` + 打「止盈」，根因就是把起点设成了当日最高；
7. **冷池退时启用保守混合**：`fl_pc_use = max(fl_pc, fl_grid_pc, 1 − P(≤floor_max))`；
8. **薄盘 `bid = 0` 不判止盈**（`_no_liquidity = mk <= 0.0`）—— 无买盘时「市价高于公允」无意义。

⚠ **别只看主表首屏就下结论。** 判读顺序：**先确认有没有「⚠作废(冷池)」标记 → 有则整表弃用 → 跑 `--watch`。**

#### ⚠ 判据里的浮点等值边界必须加容差 `[v0.19.13，2026-09-20 实测]`

冷池判定式写的是「落差 **> 0.5°C**」，本意是「恰好 0.50 不触发」。但 0.1°C 序列的两位小数
相减带浮点残差：

```python
>>> 32.2 - 31.7
0.5000000000000036      # > 0.5 → True，冷池被误触发
```

2026-09-20 13:00 实际踩到：主表把 32 档及以上整段标「⚠作废(冷池日)」，而当天
**全港 18 个分区雨量全为 0mm、UV 8、无任何生效警告** —— 那 0.5°C 只是正午常规振荡
（09-12 同样有 0.5°C 的中午下探，其后仍冲到 33.1）。

雪上加霜的是精度不一致：`_load_cold_pool_gap()` 落盘用 `round(,3)`，内存里不 round ——
于是**内存判触发、文件读回不触发**，同一天的结论会随运行路径随机变化。

**两条硬纪律：**
1. **一切「恰好等于阈值」的判定式，比较时加显式容差**（常量 `_CPS_EPS = 1e-6`）；
2. **内存值与落盘值必须同精度**（算完立刻 `round(_cold_gap, 3)` 再存再用）。

影响面仅限「最大回撤恰好 = 0.50°C」这一边界；回撤 >0.5 的日子（9/14 的 1.5、9/15 的 1.4）行为不变。

#### 冷池 vs gap：两件不同的事，别混用

| | 冷池 / 回落 gap（本节的冷池分支） | §2.4 的 gap 主判 |
|---|---|---|
| 触发 | `mx − cur ≥ 0.5` 日内记忆（最大回撤） | 当前 `running_max − 当前值` |
| 动作 | 作废**网格主表**的上三档 | 对 one-touch 分支**打折** |
| 原因 | 主表是纯气候 + 正态残差，一个实况都不吃 | R 表的条件分布变了 |

> ⚠ **仍未解决（待办）**：把实况口径并成主公允表的**单一引擎**（`--watch` 的逻辑目前只覆盖峰值，
> 不输出全档位分布）。在此之前，冷池日必须**两个引擎都跑、以 `--watch` 为准**。

#### 下午的「还会不会再涨」不能直接查 ERA5 分位表 `[v0.16.4，结构性缺陷]`

**症状**：`remaining_rise_cdf.json` 的 `by_month['9']['13']` 给出 `P(R ≤ 0.3) = 85.0%`、
`mean R = 0.127` —— 即「13 时之后再涨 0.3°C 以上」在网格里几乎从不发生。

**原因**：该表格点 (22.302, 114.173) 是**海面格**，日变化峰在 12–13 时；
HKO 站点的峰在 14–15 时。**把海面格的「峰后零升幅」搬到站点，就是把形状搞错**，
按 4.7 倍做尾部放大也补不回来。

**可用替代做法**：把 ERA5 表当**相对量**用，不当绝对概率 ——

| 口径（ERA5 9 月 h=13，n=330） | P(R > 0.3) |
|---|---:|
| 无条件 | 20.3% |
| 条件：13 时气温比 running max 低 ≥0.5°C（n=51） | **5.9%（比值 0.29）** |
| 条件：低 ≥1.0°C（n=20） | **5.0%（比值 0.25）** |

读法：**「被冷池/对流打过的日子，午后继续创新高的概率降到无条件的约三成」** ——
这个**比值**可迁移，绝对数不可迁移。
绝对概率仍须回到：① 站点自己的气候基线（旬段 × 雨量档）；② 已实现状态。
