### 2.2 L（水位）—— 站点超出网格的系统性偏移

#### 定义 `[v0.13.0]`

```
L = 今日已采样时段的中位偏差（实测 − 网格），不回归气候均值
```

旧式 `站点加成 k = 气候偏差 − 当下偏差` 会在干燥晴热天硬砍 1.4°C，是持续性冷偏差。

**9 月实测 L 台账** `[v0.23.11]`（L = 实测日峰 − 7 模式均值网格日高，格点 22.302N/114.174E）

| 日 | 14 | 15 | 16 | 17 | 18 | 19 | 20 | 21 | 23 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| L | +0.37 | +1.44 | +2.07 | +1.81 | +1.86 | +2.49 | +1.67 | +2.56 | **+2.67** |

n=8（9/14–9/21）mean **+1.78** / median +1.84 / sd **0.64**；含 9/23（+2.67）n=9 mean **+1.88**。

⚠ **这是早盘 08:00–11:00 唯一可用的中心口径** —— R 锚点 11:00 才起锚，引擎 bias 9 月已证系统性偏低
0.4–1.5°C（9/23 偏 −1.50）。
用法：`l_integrate.py --hour <h> --l-hat <近期L>`
（**必须显式覆盖 `--l-hat`**；缺省取引擎 bias +0.99，早盘会低估约 0.9°C ——
9/24 实测：默认给中心 30.88，`--l-hat 1.88` 给 31.38）。
⚠ **sd 0.64 → 区间跨约 1.3°C，只够判「μ 落在整数分水岭哪一侧」，不能定档。**
⚠ **L 无单调趋势**（最低值 +0.37 出现在 9/14 对流暴雨日）→ 不得外推为「L 在上升」。

**今天模式自己的日变化曲线只以 `δ = ρ̂ − ρ̄_h`（限幅 ±1.0°C）进入**：
气候升水已隐含在经验分布里，NWP 只贡献增量。正态会在近端高估 **41%**、远端低估 **3.4 倍**。
**δ 取代了原来手调的"已过峰值守卫"** ——
午后剩余升水自然收敛到 0。

⚠ **旧式 `peak = 当前读数 + 气候表 E[M−T_h] + k` 的斜率错了 15–140 倍**
（隐含 β=−1.0，实测 −0.007~−0.222），误差在 **13 时前后反号**：
13 时前偏冷 0.28–0.4°C，14 时后偏暖 0.3–1.0°C。

⚠ **δ 必须当随机量、不能当确定量** `[v0.15.6]`：以 `R_today = R_hist + Δ`、
`Δ ~ N(δ, (0.8|δ|)²)` 卷积，否则 δ>need 时概率会饱和到 99%。

**为什么必须卷积（两个真实故障）**：表内 `R=0`（当日在 h 时的最高已是全天最高）占比
随 h 增大而变厚（h=13 达 **60%**），旧式「把 δ 当确定量整体平移」会把该原子一起搬走，于是：
- h≥11、δ=0 给出 29 档 **62%**、δ=+0.2 给出 28 档 **0%**（两个都不可用）；
- **δ>need 时阈值穿到表最小值(0)以下 → `cdf_upper` 直接返回 `1−q[0][0]` = 99%**（伪确定性）。
  2026-09-13 13:20 实测：need=0.6（30.4→31.0）、δ=+0.77 → 脚本报 **99%**，
  而当时站点已横盘 2 小时，可辩护值仅 **~50–68%**。

**修法（v0.15.6）**：`R_today = R_hist + Δ`，`Δ ~ N(δ, (DELTA_REL_SIGMA·|δ|)²)`，
对 ε 求平均 `E[cdf_upper_delta(tbl, need − δ − ε)]`（Δ 的 1σ 取成与 |δ| 成正比）。
效果：同一情景 99% → **67%**；δ 小时与旧版几乎一致；
尾档（need ≫ δ）反而被抬高到更接近站点口径（need=2.0、δ=0.77：0.2% → **4.1%**）。
**纪律：h≥11 且需外推当日剩余升温时，仍以「实测升速 × 剩余时长 + 已观测最高截断」为主锚**，
分位表（含卷积后）只作下限参考。

✅ **one-touch 口径的实测收益（Brier，奇数年建表 / 偶数年检验）**：平均 **−25.3%**，
h=14 **−51%**、h=15 **−85%**、h=16 **−94%**。

⚠ **δ 的限幅在模式高度一致时是纯损失** `[v0.16.11 发现，待修]`
2026-09-11 09:10 实测 27.4 时 `--watch` 给**点估计 32.20**（= 网格日最高 30.7 + 水位 L 1.50），
但同一屏的概率输出说「到 30.0°C 概率约 60%」—— 两者差 2.2 °C，不可能同时成立。
**根源是 δ 的限幅**：ρ̂ = 4.80、ρ̄ = 1.92 → δ 应为 **+2.88**，
被 `max(-1.0, min(1.0, …))` 截到 **+1.00**，一次丢掉 1.88°C；
而概率**完全**由 δ 位移后的分位表决定（点估计 `pred` 只用于打印，不进分布）。
当日七模式集合离散度仅 **±0.33 °C**，模式之间已经没有分歧可按。
→ **不改代码的对策**：集合离散度 < 0.4 °C 时，把 `--watch` 的概率当**严格下界**，
改用 `--date --observed-max <实测> --mu <模式情景> --sigma 0.9` 的口径。
**彻底修复要把限幅改成随离散度自适应，并重跑 Brier 验证——验证之前不要动代码**
（v0.13.0 的 −25% Brier 改进依赖当前实现）。

⚠ **网格模拟降水未兑现 → 水位 L 虚高约 1°C** `[2026-09-13 实测]`。
今晨 09–10 时 NWP 网格报降水 1.9–2.1 mm/h，但全港实测 **0 mm**（骤雨未落地）。
时段偏差 `devs` 里掺入了「本该降温却没降」的样本，把 L 整体抬高约 1°C。
→ **纪律：用 L 之前必须先核 `rhrread` 实时雨量**；全港有雨站为 0 时 L 不可信，
改用「实测升速 × 剩余时长 + 已观测最高截断」兜底。

⚠ **watch 的 ERA5 分位表在晴热日会低估约 2°C —— 改用「同站历史日间增量」锚定**

今日 11:10 天文台站 29.0°C（已观测最高 29.3），`--watch` 给峰值 **29.80°C**。
但把 `watch.log` 里自己攒的实测轨迹拉出来对比，结论完全不同：

若基准取「已观测最高 29.3」→ **32.08**。两者取中 ≈ **31.9°C**，
比 `--watch` 的 29.80 高 **2.1°C**，直接跨一整个档位。

**根因**：`--watch` 的剩余升温来自 ERA5 25km 网格分位表，网格抹平日内尖峰
（本节已量化：9 月 h=13 的尾概率薄 4.7 倍）。**晴天无云时这个低估最严重**，

2. **分位表只作下限**，不作中心。两者相差 > 1.0°C 时以 Δ 法为准。
3. **必须先判天气型**：9/14 那种阴凉型 Δ 只有 +1.5，用晴热型 Δ 会高估 1.3°C。
   判据：全港自动站相对天文台的温差（今日 +2~3 是晴热型）、有无降水、云量。
4. 该法**只用本站历史**，不碰网格，天然是站点口径 —— 是 archive 攒够前的过渡解。

🚨 **Δ 表的样本内 sd 把概率分布做成了针尖 —— 这是 9/15–9/16 过度自信的直接来源**
`[v0.16.31，2026-09-16 复盘，ASOS n=300]`

用 4 个点算出的 sd = 0.24，而同期真实站点尺度（ASOS 机场站 9 月 h=11，n=300）**sd = 0.93**。
差近 4 倍。以 0.24 建正态 → 「31 档 88% / 32 档 12%」这类**假精确**；
以 0.93 建 → 同一中心下中间档厚得多。

禁止用 n≤5 的样本内 sd 生成任何档位概率。**

| 日期 | 峰值 | 峰值时刻 | 特征 |

不再含增量信息。此时必须切到 Δ 法。**

🚨 **Δ 法必须配「实时升速门控」—— 否则会在午后高估 0.8°C** `[v0.16.30，2026-09-16 当日翻车]`

9/16 13:40 用 Δ(13:00)=+1.40 / Δ(13:30)=+1.10 两条路径都算出峰值 **32.10**，据此判断
"32 档 54%"，并建议卖出 32 NO（@0.760）。**40 分钟后被证伪**：

| 方案 | 9/16 13:30→14:10 升速 | 结果 |
|---|---|---|
| 9/13 | +1.1°C / 20 min（**3.3 °C/h**） | 13:50 冲到 31.5 见顶 |
| 9/11 | — | 14:30 到 32.5 |
| 9/12 | — | 15:30 到 33.1 |
| **9/16** | **+0.2°C / 40 min（0.3 °C/h）** | **14:10 仅 31.2，原地振荡** |

**Δ(h) 均值隐含「剩余时刻平均还有多少升幅」，但它把「已过峰前动能段」和
「仍在爬升段」混在一起。** 判据：

> **取最近 40 分钟实测升速 v40（°C/h）。**
> - `v40 ≥ 1.5` → Δ 取**均值**（或在爬升段，取均值偏上）
> - `0.5 ≤ v40 < 1.5` → Δ 取**下四分位**（≈ 均值 − 0.5×sd）
> - `v40 < 0.5` → **已过动能段，Δ 取 0**，峰值 ≈ 当前已观测最高

9/16 14:10 的 v40 = +0.2°C/40min = **0.3** → Δ=0 → 峰值 ≈ **31.2**，
与市场（31 档 87%）一致，**不应卖 32 NO**。

**教训：Δ 法是「天气型 + 相位」的联合外推，单看 τ 时刻的表值等于假设相位不变。**
**相位（何时见顶）每天漂移 1–2 小时，必须先过 v40 门控再查表。**

#### 硬规则 1：L 必须做**贝叶斯收缩** `[v0.16.16]`

**这是本工具目前影响最大的一条错。** `watch()` 用「今日已采样时段的整点对齐中位偏差」当 L，
**不向气候值收缩**。

```
L ~ N(μ_prior, τ²)     观测 L̂ ~ N(L, σ²)     后验 L* = (μ_prior/τ² + L̂/σ²) / (1/τ² + 1/σ²)
```

| 参数 | 取值 | 来源 |
|---|---:|---|
| `μ_prior` | **+1.012** | `model_calib.json` → `bias`（80 天，站点日最高 − 7 模式平均日最高） |
| `τ` | **0.763** | `model_calib.json` → `resid_sd`（该偏差的**逐日标准差**） |
| `L̂` / `σ` | 当日对齐样本的均值或中位 / 其标准误 | 整点对齐偏差序列 |

**2026-09-15 实测（三个整点样本 +0.23 / −0.95 / −1.40）：**

| σ | L* | 说明 |
|---:|---:|---|
| 0.48（均值的 SE） | **−0.216** | |
| 0.60（中位的 SE） | **−0.197** | ← 推荐 |
| 0.84（原始 sd） | **+0.119** | 几乎正好落在市场隐含 L 上 |

**τ（0.763）与 σ（0.48–0.84）同量级 → 数据压不过先验，收缩是强制性的。**
不收缩时点估计 29.45 / NO31 公允 95.7%；收缩后 30.18 / 86.5%。
**同一天、同一批数据，NO31 的 EV 从 +25.9% 掉到 +10.4%。**

1. **任何用当日 L 出的结论，必须同时给「收缩前 / 收缩后」两版**，并注明 τ 与 σ。
   只报不收缩值 = 系统性夸大 edge（本例夸大 2.5 倍）。
2. **σ 不得小于样本的「逐小时摆动」的 1/√n** —— 今日逐时偏差一小时摆动 1.18°C，
   把 σ 取成 0.2 会让后验几乎等于观测值，等于没收缩。
3. **何时该放弃先验**：当日出现**与先验方向相反的持续性证据**时（三个样本全为负、
   且幅度单调扩大），**下调 `μ_prior` 本身**，而不是只把它当权重。
   判据：`L̂` 落在 `N(μ_prior, τ²)` 的 5% 尾区 **且** 样本数 ≥3 且同号 → 当日先验失效。

#### 硬规则 2：L 的观测值必须是「峰值时刻的偏差」，不是逐时偏差 `[v0.16.19]`

`model_calib.json` 的 `bias`（今天 = +1.012）量的是「**日最高**」偏差；
而 `--watch` / 整点对齐得到的 `L̂` 是「**逐时**」偏差。**两者不是同一个量。**

两者的差 = **网格的午后塌陷幅度**（对流参数化的产物）。
2026-09-15 实测：`L̂(12h) = 29.4 − 29.26 = +0.14`，而网格 `13h → 16h` 塌陷
`29.47 → 28.83 = −0.64`（当日实际全港 0 mm、雷暴警告已取消 → 站点不会同样塌陷）。

```
L_day ≈ L̂(t) + 网格午后塌陷幅度 ≈ +0.14 + 0.64~0.87 ≈ +0.78 ~ +1.01
```

**恰落回气候先验 +1.012 —— 两条完全独立的路径自洽。**

1. **收缩的观测值必须是「峰值时刻的偏差」**，不是当日逐时偏差的均值。
   用逐时偏差去收缩 `L_day` 会系统性偏低（今天会把 +1.01 压到 +0.25，峰值从 30.5 压到 29.7，**整整错一个档位**）。
2. 或显式建模 `L_day = L̂(t) + 网格午后塌陷幅度`（塌陷幅度取当日网格 `峰值时刻 → 16h` 的降幅）。
3. **若当日实际有雨/多云（塌陷兑现），该修正失效** → 必须同时给「塌陷兑现 / 不兑现」两版结论，
   并把「下午是否转雨」列为唯一触发条件。

> 同日配套：站点 12:00 报 **29.4**，7 模式平均网格全天峰值只有 **29.47**
> —— 站点已追平网格峰值而网格仍认为后午会升，这就是整个修正的物理根据。

> （网格线性插值到各采样时刻，n 从 1–3 提到采样点数）→ 见 §2.11 的 B 组；

#### 硬规则 4：网格基线必须与 `model_calib` 的 bias 同源 `[v0.16.17]`

**这是本工具迄今最贵的一次口径错误：连续 6 轮盘中分析全部建立在错误的网格基线上。**

`model_calib.json` 的 `bias = +1.012`、`resid_sd = 0.763` 是用
**`MODELS` 那 7 个 NWP 模式的「平均日最高」**（80 天窗口）校准出来的。但
`hk_edge.OM_HR` 与 `l_integrate.load_context` 取的 `g_rest` 一直来自
**Open-Meteo `best_match`** —— 一个服务端加权混合，**不是**那 7 个模式的算术平均。

| 口径 | 12h | 今日日最高 | 11h 后最高 |
|---|---:|---:|---:|
| `best_match`（**过去 6 轮在用**） | 30.4 | 30.4 | 30.4 |
| 7 模式平均（**bias 的正确分母**） | 29.60 | 29.60 | 29.60 |

**差 +0.79°C，恰好横跨 30/31 档分界线。** 修正后当日三样本 L̂ 从 `+0.23 / −0.95 / −1.40`
变成 `+0.57 / −0.26 / −0.57`，均值从 −0.71 抬到 −0.09
—— **「今天异常偏凉」这个判断有一半是自己造出来的。**

1. `l_integrate.py` 的 `--grid {multimodel,best_match}` **默认必须用 `multimodel`**；
   只有在明确做「服务端最优混合」实验时才用 `best_match`。
2. **任何改动 `MODELS` 列表的操作，必须同步重算 `model_calib.json`** ——
   `bias` 的分母变了，旧校准值立刻失效。
3. 手工复核时，若发现「L̂ 的绝对值持续 >1°C 且多时点同号」，
   **先怀疑基线口径不同源，再怀疑天气异常。**

#### 硬规则 5：网格峰值时刻随口径变化，触发条件必须指定口径 `[v0.16.18]`

2026-09-15 实测：`best_match` 的峰值在 **12h（30.4）后立即塌陷到 13h 28.6**；
7 模式平均的峰值在 **13h（29.5），无塌陷**。

→ 「12:00 是网格峰值时刻」这句话**只对 best_match 成立**。
写触发条件时必须写清「哪套口径的峰值时刻」，否则会**过早宣布锁定**。
实务上：12:00 到了也要看 13:00 / 14:00。
