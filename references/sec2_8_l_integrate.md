### 2.8 L 积分与 `l_integrate.py`

**`l_integrate.py` 把「L 积分」从手算固化成脚本** `[v0.16.16]`

```bash
py -3 scripts/l_integrate.py --observed-max 28.6 --current 28.5 --hour 11 \
    --bias -0.22 --sd-l 0.60 \
    --market "28:0.076,29:0.290,30:0.375,31:0.255,32:0.055,33:0.015" \
    --book   "28:0.066/0.085,29:0.270/0.310,30:0.360/0.390,31:0.240/0.270" \
    --bankroll 2500 --hold "29:0.700:172:N,29:0.290:185:Y,31:0.740:338:N"
```

它做四件事，全部是手算容易做错的：
1. **对 `L ~ N(L_hat, sd_L)` 网格积分**，每个 L 下算「经验 one-touch（δ 当随机量）」与
   「正态截断」两口径各半混合，再按密度加权。
2. **反解市场隐含 L**（`--market`）：找使模型分布最贴近市场归一价的 L。
   这是「我方与市场的分歧值多少摄氏度」的单一量化口径。
3. **组合结算回收矩阵**（`--hold`）：逐结算档算回收，识别「多腿同档归零」的缺口。
4. **真实可成交价的 EV 排序**（`--book`）：买 YES 用 YES ask、买 NO 用 `1 − YES bid`。
   **必须用 `--book`，不要用 `--market` 的 mid 算 EV** —— 29 档点差 0.04，
   用 mid 会把 +21% 的 EV 虚报成 +12%，方向都反。

⚠ **两个易错的口径（已修，别再犯）**：
- **分布中心绝不能用 `Σ k·P_k`**：档内质量紧贴现测值时集中在下缘，
  `Σk·P_k` 会系统性低估 0.4–0.5°C（实测 29.59 vs 尾和积分 30.06，而点估计是 30.04）。
  必须用**尾和积分** `E = floor + Σ ∫ P(max≥x) dx`（脚本内 `mean_from_buckets()`）。
- **市场隐含 L 对「用哪个小时的分位表」不稳定**：h=10 反解 +0.15（RMS 12.8%）、
  h=11 反解 +0.39（RMS 8.4%）。**做跨时点比较时必须固定同一个小时。**

**✅ `running_max` 贴近档位边界时，L 积分会系统性抬高下边界档位** `[v0.16.20]`

2026-09-15 12:33 实测同一个 L 中心、两种口径的 29 档概率差 **6.2 个点**：
```
mx = 29.6（距 30.0 边界仅 0.4°C）
单点 L=+0.90 → 29 档 19.0%
L 积分        → 29 档 25.2%      （+6.2pt）
```
**机理**：L 积分把 L 的分布铺开。当 `mx` 紧贴某条档位边界时，
**每一个偏低的 L 分支都把 `pred` 推过边界，整块质量直接落进低一档**；
而偏高分支只让当前档变宽（因为上一档的边界还远）。

**硬规则：`mx` 距最近的档位边界 < 0.5°C 时，该「下边界档位」的概率必须以
单点（`L = L_hat`）口径作为下界报出，不得只报积分值。**
判定边界距离用 `min(mx − floor(mx), ceil(mx) − mx)`。

**组合层：结算档 → 回收矩阵** `[v0.16.13]`

**问题**：多头寸时，逐腿算 EV 会漏掉「好几条腿在同一个档位一起归零」这个风险。
2026-09-15 的 `NO29 172 / NO31 267 / YES32 282` 就是例子：三条腿在 **31 档只回收 1/3**，
而 31 档恰是单点最大概率（38.4%）。

**做法**：列出结算档 × 每腿是否派息（0/1）× 份数，得到「档 → 回收金额」矩阵，
再用当日公允分布加权求期望，与现市值（按 bid）对比。

**读法三条**
1. **先找缺口档**：回收 / 市值最低的那一档，就是组合的真实风险点，不是单腿 EV。
2. **修缺口有两个等价动作**：卖 NO at `p` ≡ 买 YES at `1−p`。选**不增加本金**的那个。
3. **若各腿的「卖 vs 持有」差异与 sd 不确定性同量级，就不该交易** —— 那只是支付点差。
   2026-09-15 实测：NO31 的结论在 sd 0.76↔1.24 之间翻转 **27pp**，此时任何加减仓建议都是噪声。

**配套：`scripts/l_cond_check.py`** `[v0.16.17]`

把 `running_max(h)` 当**条件变量**，回答「历史上 9 月里，到 h 时已经升到这个水平的日子，
最终日最高是多少」，并顺带诊断 ERA5 的振幅压缩：

```bash
py -3 scripts/l_cond_check.py --rm11 29.07 --cur 28.5
```

2026-09-15 的发现：ERA5 在站点坐标把 9 月日最高平滑掉 **+2.2 ~ +2.4°C**
（ERA5 均值 29.23 vs HKO 站 31.64）。所以：
- `remaining_rise_cdf.json` 的 R 表**只能当「形状」用**，绝对值不可信；
  `l_integrate` 里靠 `δ = ρ̂ − tbl.mean` 把均值对齐，这个设计是必要的、正确的。
- **别拿「气候平均 bias = +2.4」去修当天的网格值** —— 会推出 32°C+ 的荒谬峰值。
  **气候平均偏差 ≠ 当日偏移量**，后者必须靠收缩（§2.2-硬规则1）估计。

**配套：市场拟合 RMS 是「市场是否讲得通」的体检指标**

| RMS | 判读 |
|---|---|
| `< 8%` | 市场分布形状可信，可以拿它当先验 / 参照 |
| `8–10%` | 谨慎，只作方向参考 |
| **`> 10%`** | **市场的形状本身不可信，不能拿它当先验** |

2026-09-15 11:23 实测 RMS **13.2%**（前一时点 8.4%），且市场分布是**双峰**
（29° 25.6% / 30° 28.9% / 31° 31.8%）—— 而任何气温分布都该是单峰。
**这是薄流动性被两组观点撕开的价格，不是一条信息。**
