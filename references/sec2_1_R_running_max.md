### 2.0 概率口径总则：条件 vs 边缘 `[v0.16.25]`

同一时刻（14:30，rm≈31）的实测：

```
gap≤0.5 → 30.8% (n=26)     gap>0.5 → 5.0% (n=20)
加权平均 = (26×30.8 + 20×5.0)/46 = 19.6%
l_integrate 同时刻给出            = 22.0%     ← 吻合
```

**网格模型没有偏低。它回答的是「平均而言还能升多少」（边缘概率），
它的 R 分位表按「时刻」建，根本没有 `gap` 这个自变量。**

→ **报概率时必须声明是条件还是边缘**：
- **下注用条件**（gap 分侧）；
- **校准 / 算 Brier 用边缘**。

> ⚠ 前几轮把两者当「两个互斥估计」互争，**是口径错误，不是模型错误**（v0.16.25 解开）。

**核心认知（决定这个工具有没有用）**

Edge **不是**来自比天文台更会预报天气。它来自三个结构性错配：
1. **结算只认一个传感器**——天文台总部站（尖沙咀）。机场、打鼓岭、手机 App 的数都不作数。
2. **市场把点预报当概率**——但结算是 0.1°C 精度的一维分箱 `floor()`，两者系统性错配
   （实测偏左：`-1` 档占 43.7%，命中市场定价档仅 31.0%）。
3. **时区窗口**——香港白天是美东深夜，挂单薄，错误定价停留更久；实况每小时更新而官方 CLMMAXT 定稿滞后。

**每次出手前必须记住**：即使完美预知当日期望最高温，命中那个整数档的概率也只有约 31–40%。
永远不要用单档全仓去"猜"。

### 2.1 R（剩余升温）—— 基准必须是 `running_max`

**分位表 `remaining_rise_cdf.json` 的原生定义写在生成脚本表头，以它为准**：

```python
"def": "R(h) = M - running_max(h)  (remaining rise, >= 0)"
```

**「已触碰」是吸收态** —— 日最高一旦观测到就不会被抹掉。所以
`P(日终最高 ≥ b) = P(R ≥ b − running_max)`。

#### 曾经踩的坑：用当前瞬时值当基准 `[v0.16.22 修]`

`--watch` 支路长期写的是 `need = b − hko_t`（当前值）。涨势日里 `hko_t ≈ running_max`，
两者相等，所以**这个 bug 藏了很久**，直到回落 1.2°C 才暴露：

| | 基准 | need（到 32.0°C） | 报出的概率 |
|---|---|---:|---:|
| 旧（错） | 当前 30.2 | **+1.8** | ~0% |
| 新（对） | 峰值 31.4 | **+0.6** | 11%（站点口径） |

用当前值等于隐含「已回落的部分会自动涨回去」——**回落日必错，误差是倍数级**。

> ⚠ **v0.16.9 曾把这件事写反**（当时称「当前值起算 = 严格口径」，并担心「峰值起算 = 假设会涨回去」）。
> 该节已整体作废，见 `references/archive_retracted.md`（7-A-1）。**同一个分位表在两种 base 下差 11 倍**，见下表。

**同一 ERA5 九月样本（2015–2025，n=330）上两种 base 的差距** `[v0.16.12 实测]`：

| 统计量 | 定义 | P(≥0.4) | P(≥0.9) | P(≥1.4) |
|---|---|---:|---:|---:|
| `D` | 日最高 − **14 时瞬时值** | **30.9%** | 14.5% | 6.4% |
| `R14` | 日最高 − **截至14时最高** | **2.7%** | 0.3% | 0.0% |
| `R13` | 日最高 − 截至13时最高 | 9.4% | 2.1% | 0.0% |
| `R15` | 日最高 − 截至15时最高 | 0.9% | 0.0% | 0.0% |

`D` 比 `R` 大 11 倍的原因：`D>0` 里混进了大量「日最高出现在 14 时之前、14 时已回落」的日子
（九月占 ~33%），这些日子在 `D` 口径下被误算成「还有升温空间」。**用 `D` 会系统性高估尾档。**

✅ **分位表本身是准的**：`R14` 实算 2.7% vs `--watch` 表 3.0%，`R13` 实算 9.4% vs 表 10.0%。

复现口径（需要时重跑）：
```python
# ERA5 archive，逐时 temperature_2m，按日取
up14 = max(v for hh, v in vs.items() if hh <= '14')   # 截至14时的最高
R14  = max(vs.values()) - up14                        # ← 这才是分位表定义
```

#### 同一件事的两个致命口径陷阱 `[v0.16.0 实测]`

**陷阱一：喂分位表前必须先取官方 Maximum Since Midnight，不能用当前值。**
冷池场景下两者能差 1.8°C：2026-09-14 11:30 站点当前 **26.9**、running max 却是 **28.7**。
用 26.9 算会把「回到风暴前水平（+2.1°C）」当成罕见事件；用 28.7 算才是正确问法。

**陷阱二：22.302/114.173 在 archive 里是「海面格点」。**
该坐标位于维港水域，2015–2025 年九月日均最高的均值只有 **25.09°C（sd 4.60）**，
比天文台站气候值（31.60）低 **6.5°C**，样本里甚至出现「九月日最高 6°C」的荒谬值。
→ **绝对水平完全不可用，只能取差分/形状。**
可迁移度排序：**差分 > 逐时增量 > 绝对温度（后者一律丢弃）**。实测差分：

| 口径（2015–2025 九月，n=3683） | P(R≥0.3) | P(R≥1.3) | P(R≥2.3) | P(R≥3.3) |
|---|---:|---:|---:|---:|
| 海点格点 R | 80.2% | 27.8% | 8.3% | 2.0% |

与 `by_hour['11']` 分位表自洽（P(R≥0.3) ≈ 75–80%），可当独立第三条轴用。
但海点日振幅被压低、理论上**低估** R，故由此算出的概率应视作**保守下界**。

#### 同时修掉的三件事 `[v0.16.22]`

1. **δ 归零**：站点越过网格全天峰值时，网格的午后塌陷不再是关于今天的信号。
   旧实现让 `δ = clamp(ρ̂ − ρ̄)` 被钳到 **−1.00 下限**，把口径失效转成硬惩罚。
2. **need ÷ 放大比 k_R**（默认 2.4）：表是 ERA5 网格口径。见 §2.3。
3. **回落 ≥0.5°C 时 ×0.5**（见 §2.4）。

#### 两条路径必须同源：`station_reach_prob()` `[v0.16.22]`

`--watch` 与 `l_integrate.py` 曾各写一套概率公式，同一天同一时刻给出
**3% vs 24.4%（差 8 倍）**。现在 watch 支路调用 `hk_edge.station_reach_prob()`，
与 `l_integrate.bucket_probs_at_L` 的经验支路逐字同源。

> ⚠ 两者仍**不完全相等**，且这是结构性的、已知的：
> `l_integrate` 额外把经验支路与「正态残差支路」各半混合（后者在午后偏高达 43%，因为它
> 没有按「峰值已被观测到」收窄 σ），把 11% 抬到 24.4%。
> **11% 与 24.4% 是同一个模型的两个组件，不是两个独立证据。**

#### 实况越过网格峰值后，网格只给「形状」，不给「峰值」 `[v0.16.20]`

2026-09-15 12:20 站点 = **29.6°C**，而 7 模式平均网格的**全天峰值**只有 **29.47°C（13h）** ——
**实况已越过网格峰值，而网格的峰值时刻还没到。**

| 用途 | 是否仍有效 | 说明 |
|---|---|---|
| 形状（几点升、几点降、升几个钟头） | ✅ 仍有效 | 上午 11h→12h 网格 +0.49 / 站点 +0.5，节奏跟得上 |
| 峰值（`g_rest + L` 里的 `g_rest`） | ❌ **失效** | 它自己的峰值低于实况，继续当锚点会**系统性偏冷** |

**硬规则：一旦 `running_max > max(网格今日)`，禁止再用 `g_rest` 作为峰值锚。**
峰值必须改走两条独立路径，并显式检验二者是否收敛：

```
路径 A  校准偏差： 峰值 = 网格日最高 + model_calib.bias
路径 B  条件经验： 峰值 = running_max + R_中位 × 振幅比
        其中 R 取自「同日 ERA5 网格 R = 日最高 − rm(h)」的条件分布（当形状用），
        振幅比 = sd(站点日最高) / sd(ERA5 日最高)，2021–2024 九月实测 ≈ 1.18
```

⚠ **振幅比 ≠ 尾档放大倍数。** 1.18 量的是**无条件日最高**的整条分布宽度比；
「ERA5 剩余升温上尾薄 4.7 倍」量的是**尾部概率**。两者不可互相替代：
路径 B 用 1.18 属**保守下界**口径，故路径 B 的 p90 仍是我方下界，不是上界。

两条路径收敛（差 < 0.3°C）时可信度显著提高；发散（差 > 0.8°C）时按区间报，不得报单点。

#### `l_integrate` 的档位概率在实况远超网格中心时不可用 `[v0.16.23]`

2026-09-15 实测：`l_integrate` 的点估计中心是 `g_rest + L = 30.40°C`，而站点实况已 **31.4**。

| 口径 | P(31°C) | P(32°C) |
|---|---:|---:|
| `l_integrate`（网格 ÷ k + 正态残差各半） | **73.5%** | 24.2% |
| 市场 mid 归一 | 71.5% | 28.0% |
| **VHHH 站点条件（rm=31 + gap≤0.5）** | **~54%** | **46.4%** |

**硬规则**：当 `running_max − (g_rest + L) > 1.0°C` 时，
`l_integrate` 的**档位概率整列降级为「形状参考」**，主判改走 `station_r_probe.py`
的站点条件频率（同站、同 rm 级别、同 gap 条件）。
