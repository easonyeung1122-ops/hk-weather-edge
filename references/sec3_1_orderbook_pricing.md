### 3.1 取价：必须用订单簿，不要用最后成交价

**这是最容易让整套分析失效的一步。** Gamma API 的 `outcomePrices`（最后成交价）和
`bestBid/bestAsk` 都是**延迟指标**，只有 CLOB 订单簿是实时的。

实测同一时刻的差异（2026-09-07，临近结算、行情剧变）：

| 来源 | 30 档 | 31 档 |
|---|---:|---:|
| 最后成交价 `outcomePrices` | 0.82 | 0.15 |
| Gamma `bestBid/bestAsk` | 0.79 / 0.85 | – |
| **CLOB 订单簿（真实可成交）** | **0.962 / 0.988** | **0.010 / 0.040** |

**差 15–17 分钱。用最后成交价算出来的 EV 完全是假的。**
越接近结算、行情变化越快，最后成交价越失真。

```bash
py -3 scripts/market_prices.py 2026-09-07            # 按香港日期取盘口
py -3 scripts/market_prices.py 2026-09-08 --depth 3  # 多看几档深度
```

**算 EV 时用可执行价，不用中间价**：
- 买 YES → YES token 的 **ask**｜卖 YES → YES token 的 **bid**
- 买 NO → **NO token 自己的 ask**（NO 有独立订单簿，不要想当然用 `1 − YES bid`）
- 卖 NO → NO token 的 **bid**

⚠ **脚本对 NO 边的 EV 会系统性高估，必须手工复算**（2026-09-10 实测）。
`hk_edge.py` 内部把 NO 价算成 `1 − m`，而 `m` 是你传进 `--market` 的 **YES 价**。
若你传的是 YES **ask**，则 `1 − YES ask = NO 的 bid`，那是**卖出** NO 才拿得到的价格。
真买 NO 要付 **NO ask**，两者差一个价差。实测：31 档脚本给 EV **+8.2%**，
按 NO ask 0.570 复算只有 **+6.3%** —— 直接从「过门槛」变成「不过门槛」。
**做法：凡脚本在 NO 边报出动作，一律用 `market_prices.py` 的 NO ask 重算一次 `P(NO)/ask − 1`。**

⚠ **中价 ≠ 可成交价：`--market` 必须喂「目标金额的扫单均价」** `[v0.16.14 实测]`
2026-09-14：30 档中价 0.180，脚本据此报「公允 20.5% → EV **+14%** → 建议 $24」；
但 CLOB 原簿是 `0.20×15 / 0.21×18 / 0.22×22 / 0.23×5 …`，**前 6 档总共只有 $20**，
按 $24 扫下来的均价是 **0.232 → 真实 EV −12%**。同一时刻 32 档中价 0.300 vs 扫单 0.353（−22%）、
33 档中价 0.075 vs 扫单 0.133（−65%）。**符号都会翻。**

```bash
# 取目标金额下的真实均价（cum$ / avg 即为应喂给 --market 的数）
py -3 scripts/market_prices.py 2026-09-14 --depth 8   # 先看有没有深度
# 再看原簿前几档，手算扫单均价：
py -3 -c "
import json,urllib.request
H={'User-Agent':'Mozilla/5.0'}
e=json.load(urllib.request.urlopen(urllib.request.Request('https://gamma-api.polymarket.com/events?slug=highest-temperature-in-hong-kong-on-september-14-2026',headers=H),timeout=30))[0]
for m in e['markets']:
    tid=json.loads(m['clobTokenIds'])
    b=json.load(urllib.request.urlopen(urllib.request.Request('https://clob.polymarket.com/book?token_id='+tid[0],headers=H),timeout=30))
    a=sorted((float(x['price']),float(x['size'])) for x in b.get('asks',[]))[:6]
    cum=sum(p*s for p,s in a); tot=sum(s for p,s in a)
    print(m['groupItemTitle'],'ask',[(round(p,2),round(s)) for p,s in a],'cum\$%.0f avg %.3f'%(cum,cum/max(tot,1e-9)))
"
```

**纪律：`--market` 里的数 = 你打算下的那个金额的扫单均价，不是中价。**
若中价下的 EV 是 +10%、扫单均价下变成 −10%，说明这条腿的 edge 只存在于薄簿的前几十美元里 —— 那就是没有 edge。

⚠ **薄盘报价会在几十秒内漂移，单次取价不算数 —— 必须间隔 15–20s 连取 2–3 次**（2026-09-12 实测）。
当日 24h 成交额 **30135 完全未变**（零成交），但报价在 30 分钟内：
- 33 档 YES **0.200 → 0.340**（+70%），31 档 mid **0.310 → 0.260**，32 档 mid **0.530 → 0.460**
- 三个档位的 ask 侧深度只有 **37–128 份**（$10–40 量级）

去水分后的隐含分布出现 **33 档（28%）> 31 档（24%）** 的形状 —— 在任何合理模型下都讲不通，
纯属薄盘噪声。**结论：该市场的报价只在「多档同时、连续多次取样」下才有信息量。**

```bash
# 稳定性采样：连取 3 次，看哪些档位是稳的
for i in 1 2 3; do date "+%H:%M:%S"; py -3 scripts/market_prices.py 2026-09-12 --depth 3; sleep 20; done
```

⚠ **薄盘环境下「市场隐含 L」全天不可用** `[v0.16.21 实测]`

2026-09-15 13:00–13:15，Polymarket 31 档 YES mid 走完
**0.520 → 0.880 → 0.540 → 0.880 → 0.710** 五个来回，全程 15 分钟：

| 采样时刻 | 31 档 bid/ask | 最优档深度 | 32 档 bid |
|---|---|---:|---:|
| 13:04:58 | 0.540 / 0.600 | 86–138 | 0.380 |
| 13:05:12 | 0.570 / 0.620 | 32–61 | 0.310 |
| 13:05:25 | 0.540 / 0.620 | 60–104 | 0.300 |
| 13:10:31 | 0.880 / 0.910 | 59–121 | 0.060 |
| 13:14 | 0.560 / **0.860** | 437–483 | 0.140 |

**买卖价差最宽 0.30**（对 34/35 档是 0.002/0.004）—— 这不是市场，是断档。
今天的「市场隐含 L」在 15 分钟内从 **+2.03** 跳到 **+2.41** 再回落。

**硬规则（把原来的「薄盘警报」升级）**：
1. **某档最优档深度 < 200 份时，该档的 mid 移动一律不得当作信息**，
   更不得据此反解「市场隐含 L」。
2. **买卖价差 > 0.15 时，只能用「挂在价差里」的限价单**，不得按 mid 计算 EV，
   也不得追价 —— 触价即支付整段价差。
3. 报价必须**连采 3 次、间隔 ≥10 秒**，三次不同则取**最差的一侧**
   （要卖就取最低 bid，要买就取最高 ask），这是唯一的保守做法。

**薄盘警报的分档判读**（同一族规则，`[v0.16.18]`）—— 看到某档 mid 在几分钟内移动 5–10 个点时，
**先查该档最优卖单的份数**：

| 最优卖单 | 判读 |
|---|---|
| ≥ 300 份 | 该移动可能是真信息 |
| 100–300 份 | 谨慎，需要与其他档位同步才算 |
| **< 100 份** | **该移动可能只是单笔订单，不能当作信息** |

2026-09-15 11:26→11:34，31° 档 YES mid 从 0.330 → 0.420（**9 个点**），
而该档**最优卖单只有 74 份**，同期站点预报、雨量、警告、网格全部无变化 → 只能当「观点撕扯」。

**算完 Kelly 必须再核对可成交量**（见 §3.5）。临近结算时经常出现
「EV **+150%** 但只能买 165 份（≈**$6.6**）」—— 这种 edge 真实但不值得动手。

**极端定价出现时，读完整档阶梯而不是 top-of-book**（2026-09-12）

**场景**：13:44 时 31°C 档 YES 报价 `0.001 / 0.002`，而快照最高值 31.9 距上界仅 0.1°C。
表面读法：「市场 99.8% 确定冲上 32，31 档已死」→ 不敢碰。**正确读法**：拉完整 ask 阶梯再看。

| 价位 | 份数 | 累计成本 | 累计均价 |
|---:|---:|---:|---:|
| 0.002 | 1653 | $3.31 | 0.0020 |
| 0.003–0.009 | 778 | $8.11 | 0.0033 |
| **0.010** | **4586** | **$53.98** | **0.0077** |

→ **$54 能买下 7018 份**，若 31 档结算则赔付 $7018。**top-of-book 的 0.002 只是冰山一角。**

**纪律**：当某档价格 ≤ 公允值的 1/10 时，必须跑一次完整档阶梯（`--depth 40` 或直连 CLOB
`/book?token_id=`），算出「按公允概率的 EV / 最大可买成本」，再判断值不值得动手。
