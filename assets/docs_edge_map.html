一句话结论：你的 edge 不来自"比香港天文台更会预报天气"——官方 9 天预报已经极准。 你的 edge 来自三件事：① 只有天文台总部站（尖沙咀）那一个传感器说了算； ② 市场把"点预报"当"概率"，而结算是 0.1°C 精度的一维分箱； ③ 你在香港的时区里，能在欧美做市商睡觉时实时盯住那个传感器。

1 · Edge ①：站点认知差 —— 天文台站比"大家看的那个数"系统性偏低

香港地形破碎，同一个下午，新界内陆和尖沙咀海旁能差 2–4 °C。结算只认一个点。下面是用天文台官方 CLMMAXT 数据（2016–2026，同日配对）算出的天文台站日最高温 减去 各站的差值：

读法：正数 = 天文台更热，负数 = 天文台更凉。

  • 石岗 −1.15 °C、打鼓岭 −0.89 °C：新界内陆站夏季几乎每天都比尖沙咀热约 1 °C。新闻标题"打鼓岭 35°C"时，结算站大概率 33–34 °C。
  • 京士柏 +0.41 °C（夏季）：京士柏就在天文台山旁边，是全港与结算站相关性最高的代理站——用它做实时代理变量最好。
  • 长洲 +0.61 °C（夏季）：离岛没有城市热岛。
怎么变成钱：每当有"全港酷热 / 某区破纪录"的本地新闻，散户会推高高价位档（33、34、35°C）。 你只要记住"结算站是尖沙咀那台，比新界低约 1°C"，就能在错误定价时站在对家。

偏差修正后 RMSE 只有 0.79 °C——已经很接近香港天文台官方预报的水平（实测官方 9 天预报 与该方法几乎重合）。但重点来了：

即使你能完美预知当天的期望最高温，命中那个整数档的概率也只有 ~31%。
回测里"预测值取整天数 = 实际结算档"的命中率：31% （n=87，提前 0–1 天）。理论值（误差 ~N(0, 0.80)）为 39.6%。

为什么？因为"四舍五入"和"向下取整"打架

官方预报是整数（四舍五入），结算是 floor。当预测值是 32.6（官方报 33），实际 32.9 落在 32 档——相对官方档偏 −1。这造成实测偏移分布明显左偏：

实际结算档 − 官方预报档实测频率
−2 档及以下10.3%
−1 档43.7%最容易买错的地方
0 档（市场定价档）31.0%
+1 档14.9%
可直接执行的推论：如果某个档的市场价被推到 50–70%（散户看到官方预报写 33 就一窝蜂买 33）， 而你的集合分布告诉你它只有 30–35%，那么买 NO（或卖空该档）的期望值极高： 市场价 50% vs 真实 31% → 买 NO 每 $1 收回约 $1.38。
反之，紧邻的 −1 档（43.7% 的偏移概率）常被严重低估。

3 · Edge ③：时区与流动性 —— 你人在这里，就是优势

  • 香港白天 = 美东深夜。欧美做市商睡觉时，香港气温盘的挂单变薄、价差拉宽、错误定价停留更久。你在办公室刷一下手机就能捡。
  • 结算数据发布有时间差。天文台 CLMMAXT 通常滞后数天才定稿（此刻最新到 2026-08-31），而实时逐时观测（rhrread API）是每小时更新的。 当天下午你用实时数据几乎已知答案，但要等官方定稿才结算——中间那段"你已经知道、市场还没完全收敛"的窗口，就是你的 alpha。
  • 日最高温出现时刻有规律但也有例外。晴天峰值集中在 14:00–16:00，之后基本锁定； 但阴雨 / 暖湿平流时峰值可能出现在夜间（暖空气夜间输送），市场仍按晴天逻辑定价——这是最典型的定价错误。
  • 台风是最大非线性。天文台挂波前后，官方预报会大幅跳变，市场反应滞后数小时。台风季（7–9 月）edge 最大也最危险。

4 · Edge ④：微观结构

  • 用限价单做 maker。Polymarket 大部分品类 maker 零手续费甚至有返佣，taker 有费用。薄盘市场里，挂单比吃单每年省下几个百分点。
  • 跨档梯度下注（ladder）。别梭哈一个档。把资金铺在你的分布支撑的 2–3 个相邻档上，收割分布形状而不是猜单点。
  • Kelly：二元合约买 YES 的最优仓位 f* = (p − m) / (1 − m)，其中 p = 你的公允概率，m = 市场价。 实践中用 1/4 ~ 1/2 Kelly——你的 p 本身有模型误差。
  • 只在 |edge| > 8% 时出手。0.79 °C 的 RMSE 意味着你的概率估计本身有 ±5% 量级的不确定性，太小的 edge 会被自己的误差吃掉。

5 · 工具：把上面全部自动化

仓库里这个脚本把所有步骤串起来了（数据全部来自公开免费 API，无需 key）：

cd /workspace/hk_weather_edge

# 未来 7 天所有档位的公允概率
python3 hk_edge.py

# 只看某一天 + 手工喂入市场价，直接算 edge
python3 hk_edge.py --date 2026-09-08 --market "31:0.45,32:0.32,33:0.10"

# 当日实时追踪（建议 cron 每 10 分钟跑一次，自动累计当日最高温）
python3 hk_edge.py --watch

# 生成 HTML 报告
python3 hk_edge.py --html

数据流：

用途来源
结算源历史（回测/校准）HKO Open Data CLMMAXT&station=HKO
实时各站温度（含天文台站）HKO rhrread（每小时更新）
官方锚（市场看的就是它）HKO fnd 九天预报 forecastMaxtemp
多模型确定性融合Open-Meteo：ECMWF IFS / GFS / ICON / GEM / METNO / JMA / UKMO
概率分布Open-Meteo Ensemble（ECMWF 50 成员）+ 偏差修正 + 残差平滑

核心算法是气象学里标准的 dressed ensemble：把 50 个集合成员各自加上偏差修正，再叠加回测残差噪声 N(0, 0.78)，然后对 [N, N+1) 积分求平均。这样得到的分布会随提前期自动变宽—— 提前 6 天很散，当天下午很尖，正好对应不确定性衰减。

7 · 每日工作流（15 分钟）

  1. 14:00 HKT：天文台更新九天预报后，跑 python3 hk_edge.py，看未来 4 天各档公允概率。
  2. 打开 Polymarket 对应日期，把各档价格抄进 --market，让脚本标出 +EV 的档。
  3. 只在 |edge| > 8% 的档挂限价单，做 maker，别吃单。
  4. 09:00–16:00 HKT：cron 每 10 分钟跑 --watch，实时知道天文台站今日已观测最高温。
  5. 晴天 16:00 后峰值基本锁定 → 果断平仓或加仓；阴雨天保持警惕，峰值可能出现在夜里。
  6. 记录每笔的"你的概率 vs 市场价 vs 结果"，30 笔后回头校准自己的命中率。

8 · 风险与合规（认真读）

  • 合规：香港《赌博条例》(Cap. 148) 下，预测市场处于灰色地带——未被明确许可，也未见针对此类平台的执法。 SFC 未就预测市场表态。这不构成法律意见，请自行评估，或咨询香港律师。
  • 模型风险：0.79 °C 的 RMSE 在档位边界上就是真金白银。回测窗口只有 92 天（2026-06-06 起）， 样本偏夏季，冬季表现需要你自己积累数据后再校准。
  • 流动性风险：香港气温盘单日成交量在 $0.1M–$0.25M 量级，冷门档位可能根本没人接你的单。
  • 结算风险：规则写明"初始发布后的修订不予考虑"，但天文台确实偶有数据质量修订； disputed 结算会进 UMA 仲裁。
  • 别用 VPN 绕过地区限制——违反 ToS 且可能被封号冻结资金。
